# 前提差值符号的反例对照（2026-09-28）

运行位置：原仓库 `frontend`。命令：`node --test src/features/ai-assistant/premiseSignAdversarialEval.test.js`。样本均为人工构造的题设与已确认草稿文字；没有调用真实 Provider 或识别服务。每例经过独立工具、已提交草稿、局部目标、Context Engine 和提示回复块。`providerEligible` 仅表示本地上下文允许进入模型路径；`mockRevealEvent` 是人工注入短提示后的模拟展示结果。

| 样本 | 核心变化 | 预期与修复后工具状态 | 本地路径 |
|---|---|---|---|
| PS01 | `a>b` 与 `a-b>0` | valid | 允许模型路径，前提仍标未验证整步 |
| PS02 | `a>b` 与 `a-b<0` | invalid | 核验块，模型路径和提示揭示均停止 |
| PS03 | 反向差值 `b-a>0` | invalid | 同上 |
| PS04 | 题设后文出现“当…时”分支 | unknown | 允许模型路径，保持未验证 |
| PS05 | 题设后文另有 `a=b` | unknown | 同上 |
| PS06 | 题设后文“令 `a=b`” | unknown | 同上 |
| PS07 | 已确认文字 `a−b＜0` | invalid | 等价符号核对后停止 |
| PS08 | 题设 `x＞y`、草稿 `x−y＞0` | valid | 允许模型路径，保持原文 |
| PS09 | 易混淆的排版短横 `a–b` | unknown | 允许模型路径，保持未验证 |
| PS10 | 引述并否定错误声明 | unknown | 同上 |
| PS11 | 条件与声明变量不一致 | unknown | 同上 |
| PS12 | 转录中有 `?` 未识别字符 | unknown | 同上 |
| PS13 | 与差值无关的合法分支 | unknown | 保守放弃核验，不误报冲突 |
| PS14 | 变量换成 `p,q`，反向差值使用等价符号 | invalid | 核验块，模型路径和揭示停止 |

首轮 12 例中，PS04–PS06 被误判为 `invalid`，PS07–PS08 落到 `unknown`。修复后，14 例全部符合预期：4 个 `invalid`、2 个 `valid`、8 个 `unknown`。工具仅统一无歧义的 Unicode 数学减号 `−` 及全角 `＞＜＝`；排版短横、未识别字符和未支持的命题结构不做猜测。题设开头条件后的新关系号或分支词现在使工具返回 `unknown`，即使某个分支实际上不影响该差值；这是有意保留的漏报边界。

`unknown` 仍可进入模型提示路径，模拟回复会生成带未验证警示的 Hint 和揭示事件。因此这组测试**不能证明**模型不会错误肯定复杂前提。浏览器旅程另验证 ASCII 冲突被拦截，以及用户把已确认文字改为 `a−b＞0`、提交新版后可以继续提示；它未测试真实 OCR 对图片的识读质量。下一轮应优先评估复杂前提下模型错误肯定的可复现样本与展示策略，再决定是否增加新工具语法或守卫。
