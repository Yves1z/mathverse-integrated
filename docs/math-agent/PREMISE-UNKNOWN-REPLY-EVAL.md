第一轮修复前 UE01 显示为 Hint 并产生揭示事件。第二轮试错前 UE05–UE08 同样漏拦截；现在十八例均符合上述预期。守卫只在局部草稿提示明确选入较早前提时，识别句首或有限引入语后对**那一步或选入前提**的直接肯定，包括“没错”“是对的”和“可以放心沿用”。被拦截的回复不会把模型的话标为数学错误或工具结论；它作为 `response_guard` Warning 隐藏原文，说明尚未完整验证，提供“核对这一步”的版本绑定编辑操作，仍允许学生取消前提或主动请求完整解答。没有选入前提、提问、否定肯定或正常条件提示不被该窄守卫拦截。

页面旅程还用未支持的排版短横模拟已确认转录：第二轮改用 UE05，错误肯定被隐藏、提示级别不前进，编辑操作聚焦原草稿；下一条谨慎提示可正常显示。后续长回复、格式化断言及引用/条件对照见 `PREMISE-REPLY-SCOPE-EVAL.md`；页面当前已使用其中的加粗和编号列表失败样本。模拟回复与原草稿文本不会被上传为真实评测数据。此规则仍是有限措辞守卫，长篇推理中的隐含断言、复杂条件依赖、真实 OCR 歧义和真实模型的教学质量仍未获保证；不能把 Warning 计作前提真假判断。
