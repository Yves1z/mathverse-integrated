# 手写纠正与重试：合成失败记录

日期：2026-09-27。范围：路线图阶段 3 的识别后确认、用户修改、重试与来源保护。

这些是构造的 OCR 文字回复和指定的学生纠正，未配套真实手写图片，未调用真实识别模型。通过只证明应用契约，不能计作 OCR 准确率、数学质量或人工验收。

## 代码与规范差距

04 要求原始来源不可覆盖、识别与数学判断分离、关键歧义由用户确认；08/10 要求模型切换、失败、停止和重试保留学习输入。原代码 `HandwritingReview.vue` 在识别成功后无条件赋值 `text = result.text`，缓存命中同样执行，可能丢失学生修正。

另一个问题由样本实际捕获：六个确认前修改案例在来源状态断言处失败，实际得到 `user_confirmed`。`typedAttempt.js` 比较的是已经修正的 `handwriting.text`，而非 `handwriting.recognition.text`。现已改为比较原识别文字；手动转录仍使用独立的 `manual_transcription` 方法。

## H01–H08

| 编号 | 构造的风险 | 指定纠正/预期边界 |
|---|---|---|
| H01 | `x2=4`，识别置信度 99% | 学生改为 `x^2=4`；高置信度不能抹去修改 |
| H02 | `1/x+1` | 学生改为 `1/(x+1)`；保留分母范围候选 |
| H03 | `x=1` | 学生改为 `x-1`；未知置信度仍可手动核对 |
| H04 | `x=3` | 学生说明已划去并改为 `x=2`；不替学生选数学答案 |
| H05 | 横向情况二先于情况一 | 学生重排分支；保留顺序不确定性和原生来源 |
| H06 | 外观被转录为 `AB⊥CD` | 学生声明没有垂直条件；不把画面当成已知关系 |
| H07 | 无 OCR 历史的手动转录 | 也须明确选择替换；未修改的原识别可直接重试 |
| H08 | 不可读、截断 JSON、混入 `mathCorrect` | 阻止不可读内容进入确认；拒绝截断与诊断字段 |

H01–H06 验证：原文候选与置信度保留 → 直接覆盖被拒绝 → 修正文字确认 → 不可变来源关联 → Context Engine 接收 `user_edited_transcription` → 明确选择后才允许替换。它们不会自动识别出语义错误；纠正内容由 fixture 给定。

## 用户可见的修复

有手动输入/修改时显示“再次识别时，用新读法替换我修改或手动填写的转录”，默认不勾选；未选择时不能再次识别，但仍能核对并提交当前文字。替换选择每次使用后消耗，编辑、设置切换和来源变化会撤销。成功后再次确认读法；失败、停止、过期结果保留当前内容。识别授权和替换选择分别控制图片发送与文字覆盖。

提示词补充上下标、分数、负号、涂改、横向分支和几何外观的注意事项。提示词无法可靠拒绝一个格式合法却语义错误的转录，仍需学生核对或未来真实识别评测。
