# 局部草稿提示的成对失败样本（2026-09-28）

运行位置：原仓库 `frontend`。命令：`node --test src/features/ai-assistant/localHintPairedEval.test.js`。四个案例共享原创题“已知实数 `a>b>0`，研究 `ln((a-b)/b)` 是否有定义”和六步学生草稿；第 5 步是提示目标，第 1 步是可选择的较早前提，第 6 步含不应传出的答案。第三例只把第 1 步改成错误的 `a-b<0`。所有模型回复均为**人工编造的输入**，脚本不调用 Provider，也不需要 API Key。

| 样本 | 请求范围（草稿步号） | 注入的回复 | 可确定的观察 | 数学/教学结论 |
|---|---|---|---|---|
| LH01 缺远处前提 | 3、4、5 | “先核对对数真数需要满足什么条件。” | 第 1、2、6 步、参考答案及旧提示正文未发送；提示级别 0；模拟回复显示为 Hint | 只证明缺前提时的范围与提示入口，不能证明真实模型会问对问题 |
| LH02 学生补入前提 | 1、3、4、5 | “回看第一步给出的符号条件……” | 与 LH01 同一目标，仅增加原草稿第 1 步及其来源区间；明确标为尚未验证；提示级别仍为 0 | 不能由模拟回复证明该前提必要、路线保留或学生能独立继续 |
| LH03 冲突前提 | 无模型请求 | **故意错误**：“第一步完全正确，可以直接沿用。”（现已拦截，未发送） | 窄范围差值符号工具核对第 1 步的 `a-b<0` 与题设 `a>b` 冲突；显示来源清楚的核验块和整步未验证警示，无 Hint 揭示事件 | 原开放失败在支持的语法内已修复；不能由此证明整步正确性或推广到其他前提 |
| LH04 后续藏有答案 | 1、3、4、5 | “答案为 0” | 第 6 步与参考解未发送；修复后该同义答案句式显示为 Warning，无 Hint 揭示事件；浏览器刷新后已看提示数不增加 | 只拦截这一类明显句式，近似完整解法或隐晦泄露仍未得到语义证明 |

这组对照记录 Context 范围、Hint Level、显示块类型和揭示事件；“是否命中真实 blocker、前提是否必要、是否保留学生路线、能否促进独立进展”均标为**未验证**。LH03 的故意错误回复保留为回归注入值；在支持的符号条件内，冲突先于模型请求被阻断。原始失败以及修复后的范围均被记录，测试通过不表示教学质量通过。

试错中发现旧的明显答案守卫会隐藏“最终答案：0”，却放过“答案为 0”。`responseBlocks.js` 已补这一窄句式，并保留“答案为什么……”等问题表达；单元与浏览器测试确认警示不推进已揭示次数。不要把这个正则视为完整的语义级泄露防护。

2026-09-28 的修复仅覆盖题设开头明确的单字母严格大小关系及学生选中单条差值符号断言。`valid`、`invalid` 和 `unknown`、反向差值、旧版/新版草稿、否定与复合前提已有单元样本；新浏览器旅程验证按钮和自然语言入口、拦截后的修改/重新选择/继续提示。验证块只声明差值符号，额外警示整步未验证。下一步扩充合法分支和反向条件的对照库，再考虑扩宽数学工具。真实模型、教师和学生验收继续单列，不能用这四条模拟回复抵充。
