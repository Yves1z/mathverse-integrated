# Mathverse AI 学习助手开发计划

> 本文件是 AI 功能的长期状态与决策记录。后续开发开始前先阅读本文件；完成工作后更新阶段状态、验证结果和变更日志。不要只依赖聊天记录恢复上下文。

## 1. 产品定位

Mathverse AI 不是一个独立的通用聊天框，而是连接当前页面、题库、标签体系、训练记录和站内操作的“数学学习操作层”。它的差异化价值来自：

1. 自动获得用户明确选择的页面上下文，不要求重复复制题目。
2. 使用 Mathverse 标准知识点、题型与方法标签，而不是自由生成不可复用的词语。
3. 从站内真实题库检索、引用并操作题目，不伪造资源。
4. 将输出转成可执行结果，例如推荐题、标签建议、练习清单和组卷条件。
5. 用检索、结构化输出和确定性校验增强模型，而不是简单增加输出长度。

## 2. 当前商业与密钥策略

- 当前阶段：用户自带 API Key（BYOK）为主。
- 默认安全策略：Key 只保存在当前前端运行内存和单次中转请求中，不写入仓库、localStorage 或 sessionStorage。
- 浏览器不直连模型厂商；请求经过 Mathverse 同源中转，限定官方 HTTPS 域名和 Chat Completions 路径。
- 后续盈利阶段：增加 Mathverse 官方 API 额度、会员配额、限流和成本核算；BYOK 继续作为高级选项。
- 页面必须明确显示厂商、模型、是否真实调用、是否命中缓存、Token 用量和厂商请求 ID，不能让缓存结果冒充新调用。

## 3. 交互设计

### 3.1 全局入口

- 桌面端：右侧固定触发按钮，展开为 400–460px 的抽屉。
- 移动端：底部触发按钮，展开为全屏或大尺寸底部面板。
- 抽屉可在路由切换时保留设置与对话，但页面上下文必须随路由更新。
- 打印时完全隐藏。

### 3.2 抽屉结构

1. 顶栏：Mathverse AI、当前模型、连接状态、关闭按钮。
2. 上下文区：当前页面或题目，可选择是否随请求发送。
3. 任务区：与页面相关的快捷任务卡片。
4. 对话区：用户与 AI 消息、结构化结果和错误状态。
5. 输入区：文本输入、发送、停止、清空。
6. 设置区：厂商预设、地址、模型、Key、超时、测试连接。
7. 调用区：缓存状态、请求 ID、输入/输出 Token、总 Token、耗时。

### 3.3 工作强度

- 快速：单次调用，适合连接测试、标签、摘要和简单提示。
- 标准：补充站内上下文与结构化约束，再进行一次模型调用。
- 深度：规划、解答、校验分阶段调用；执行前显示预计调用次数和成本。第一阶段只完成界面与协议，不启用多轮深度编排。

## 5. 技术架构

```text
AI Drawer / 页面内快捷按钮
              ↓
Context Builder（当前路由、当前题目、用户选择）
              ↓
Task Orchestrator（任务模板、强度、缓存策略）
              ↓
Provider Adapter（DeepSeek / Qwen / OpenAI）
              ↓
同源安全中转（域名白名单、超时、大小限制）
              ↓
Response Normalizer（文本、结构化数据、usage、request id）
              ↓
站内工具与校验器（题库检索、标签词表、数学校验）
```

统一请求至少包含：`taskType`、`messages`、`context`、`provider`、`model`、`mode`、`timeoutSeconds`。统一响应至少包含：`content`、`model`、`usage`、`providerRequestId`、`elapsedMs`、`cached`。

## 6. 质量与安全原则

- 当前页面内容只有在界面明确显示“将随请求发送”时才进入模型请求。
- API 错误不得自动降级成离线结果，以免掩盖连接、计费或权限问题。
- 相同任务可以缓存，但必须显示“缓存命中”，并提供“强制重新调用”。
- AI 标签只能作为建议，必须经过标准词表映射和用户确认。
- AI 题解必须区分提示、思路和完整解答，默认不直接暴露完整答案。
- 作答检查与正式评分分开；没有确定性校验和评测集之前，不提供高风险自动评分。
- 不支持的模型能力必须明确提示，不伪造图片、工具或结构化输出支持。

### 6.1 Math Agent 当前范围决策（2026-09-22）

- 选中答案或解析后只打开 AI 窗口并预填问题，由用户补充具体困惑并主动发送；不得因选择文本自动产生 API 费用。
- 第一版只覆盖答案与解析，数据协议预留题干、论坛、公式和图形上下文。
- 解析步骤先按段落、编号和换行做确定性拆分，使用“解析版本＋步骤序号＋内容指纹”形成可追踪 ID；后续再接永久步骤 ID。
- 未审核社区解析在回答前必须先由模型独立核验当前思路；错误或条件不足时先指出问题，不沿错误思路继续解释。
- 近期数学工具和可视化只覆盖高考数学，不扩展大学课程。
- 近期模型厂商继续支持 DeepSeek、Qwen、OpenAI 与受控的 OpenAI-compatible 地址，不把 Claude 纳入本阶段。

## 7. 分阶段实施

### 第一阶段：全局助手基础设施（测试版已完成）

- [x] 全局可展开/缩回的 AI 抽屉，适配桌面和移动端。
- [x] 统一个人 API 设置，与相似题页面共享内存中的 Key 和模型配置。
- [x] 当前页面上下文；题目详情页提供题号、题干、标签和可选答案/解析。
- [x] 首批任务：自由对话、解释当前题、给出提示、进入相似题推荐。
- [x] 调用元数据：真实请求、缓存、Token、请求 ID、耗时。
- [x] 快速/标准/深度模式界面；第一阶段执行快速和标准，深度模式显示为规划中。
- [x] 浏览器回归、移动端、键盘关闭和打印隐藏。

验收：用户能够在任意学习页面打开抽屉；在题目详情页无需复制题干即可发起解释或提示；相似题页和抽屉共用 API 设置；每次调用能看出是否触发厂商、是否命中缓存和 Token 用量。

- [已完成] 普通投稿页使用独立的可选入口；不打开 AI 时保持原上传流程。
- [已完成] 官方审核编辑区加入醒目的 AI 辅助分类入口，重点识别题型、D1～D7 难度和标准标签。
- [已完成] 共用结构化分析内核，可整理标题、题干、答案和解析；提示词禁止补做题目或凭空生成答案。
- [已完成] 题型、难度、标签在模型返回后再次按站内目录校验；未知标签只展示为未映射项，不能写入表单。
- [已完成] 展示字段级建议、分类依据、置信度、警告、未映射项、模型、耗时和 Token；用户逐项确认后才写入表单。
- [已完成] 社区投稿采用 AI 分类后可以把难度与标准标签送入官方审核；未使用 AI 时继续采用原默认难度和空标签。
- [已完成] 将上传规则1.4落为本地确定性规则引擎；无 API 也能检查必填字段、长度、题型、难度、标准TAG、公式定界符、材料段、HTML与图片路径。
- [已完成] AI 输出应用前再次执行规则引擎，并对数字、关系符号和 LaTeX 命令做受保护信息比对；凭空补写答案/解析或改变数学信息时阻止应用。

- [待完成] 基于题库指纹的重复题候选，不让模型凭空判断重复。
- [待完成] 建立标签准确率评测集，记录用户接受、修改和拒绝比例。

### 第三阶段：学习辅导与题库工具（进行中，选区解释测试版已完成）

- [已完成] 答案/解析按段落与编号生成可追踪步骤；选中文字后显示“解释动机、展开推导、问 AI”浮动菜单。
- [已完成] 选区只打开助手并预填可编辑问题，不自动调用 API；助手显示当前题目、解析 Step 与引用内容。
- [已完成] 请求只携带题目、当前步骤、最多两个前置步骤和一个后续步骤；社区未审核解析附加强制先核验规则。
- [已完成] 初版学习回合：快捷按钮与明确自然语言请求统一解析为提示、检查当前步或完整解答；提示按题目与步骤记录已展示层级，后续提示不复用旧缓存；提示/只检查当前步时不发送后续解析和参考答案。
- [已完成] 当前题目/步骤对话隔离；切换焦点取消旧请求并丢弃迟到结果；提示后突出“写下我的下一步”主操作，同时保留“再提示一点”和主动查看完整解答的路径。
- [已完成] 错误提供设置或重试入口；取消与清空对话保留已揭示提示记录，完整解答展示后记录为最高揭示级别。
- [部分完成] 提示、显式完整解答、普通回答、警告与算术验证已封装为受结构校验的 Response Blocks；明显越级泄露的提示会隐藏且不计入揭示记录。语义级泄露检测仍需更完整的 Guard 与评测集。
- [部分完成] 精确有理数四则运算等式由受限站内工具验证；变量、函数、证明和其他超出支持范围的步骤仍由 AI 分析并明确标为未经确定性工具验证。
- [部分完成] 提示揭示状态按账户身份和题目/步骤范围保存在浏览器标签页检查点，刷新后可恢复；API Key 不写入。完整服务端 Session/Checkpoint、跨设备恢复、正式 Context Engine 与 Learner Model 仍待完成。
- [部分完成] 新增“检验我是否真正理解”单轮入口：学生自述当前题或选中步骤，AI 只给一处简短反馈和一个追问；理解清楚时停止。暂不形成掌握度证据，完整费曼状态机与数学质量评测仍待完成。
- [待完成] 建立 20～30 个“解释动机而非复述含义”的人工评测案例。
- 分级提示：考点、突破口、下一步、完整思路、完整解答。
- 题库 RAG：检索类似题和已审核解法，再生成回答。
- 站内工具：加入题单、生成训练组、错题归因、自然语言组卷。
- 标准模式加入引用来源；深度模式加入规划和复核。

## 8. 评测指标

- 相似题：Recall@K、Top-3 命中率、无可靠结果时的拒绝率。
- 标签：标准标签准确率、用户接受率、重复标签产生率。
- 辅导：提示有效率、直接泄露答案比例、用户继续训练比例。
- 作答检查：错误检出率、误报率、无法判断率。
- 系统：首字延迟、完整延迟、成功率、缓存命中率、每任务 Token 与费用。
