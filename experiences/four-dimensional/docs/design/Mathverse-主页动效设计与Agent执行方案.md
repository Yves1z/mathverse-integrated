# Mathverse 主页动效设计与 GPT Agent 执行方案

版本：1.5
日期：2026-10-10  
用途：交给负责设计与开发的 GPT agent，作为实现、调试与验收依据。  
状态：阶段 C 基础循环、数学窗口与连接运动样例已完成，已接入整体光影、有限后期与粒子精修、欧拉人物的三章作品叙事，以及三窗口的精确视角关系拼接。用户批准“数学窗口”构想的第 1–4 部分，确定阅读窗口约 80%、外部空间约 20%，并确定抽象数学景象为主、人物窗口保留少量人的痕迹。其余新增数值与工程细节是可调默认值；窗口、光影、欧拉与视角拼接记录分别见 docs/worlds/stage-d-windows-report.md、docs/worlds/stage-d-light-report.md、docs/worlds/stage-d-euler-report.md、docs/worlds/stage-d-alignment-report.md。

## 1. 项目目标与已确认约束

制作一个仅面向电脑浏览器的 Mathverse 沉浸式主页。用户最初站在纯白空间中，面前只有一扇门；点击推开门后，连续进入具有《星际穿越》超立方体场景气质的数学空间。摄像头持续向空间深处移动，用户拖拽控制观察方向。认真观察或阅读数学对象时，位移显著减慢；退出阅读后，平滑恢复略快的探索速度。

必须保持以下决定：

- 门外为纯白空间，门是首屏视觉中心。
- 门内为有实体结构、有层次、有遮挡的空间；用户位于结构内部。
- 视觉参考优先采用电影中的超立方体／书架空间：重复、纵深、层叠、实体框架、少量暖光。
- 用户拖拽相当于扭头；前进路径与观察方向分离。
- 空间自身也缓慢变化。
- 动作安静、有重量、有柔软的收尾；保持跟手。
- 配色简单：白、黑、灰，以及极少量暖白／琥珀光。
- 阅读时保持非常缓慢的非零位移；退出后渐进恢复探索速度。
- 数学内容通过有内部世界的窗口呈现；阅读时窗口约占画面 80%，其余约 20%持续显露外部空间运动，具体构图见第 16 节。
- 只适配电脑网页，不安排手机界面、触摸交互、移动端降级或手机验收。
- 第一版先建立空间、镜头和完整交互循环；内容体系后续扩充。

本次工作范围是设计与实施方案。真正开始开发时，先读取实际项目说明与代码，确定集成位置，不能把本方案所在文件夹默认视为网站源码目录。

## 2. 体验概念与视觉判断

核心表达：从白色中的一扇门，进入持续展开的数学结构；身体向前，头可以自由观察；数学随着视角和距离逐渐显露。

用户应依次感到：安静与好奇 → 门后存在另一个世界 → 跨入空间 → 察觉深度 → 主动观察 → 发现数学 → 放慢速度理解 → 继续探索。

高维感来自三个设计机制：多方向重复的结构；同一对象在不同视角呈现不同形态；同一数学主题的多种表达同时存在于空间中。第一版以三维实时场景建立这些感受，不能在说明文案中把普通三维动效称为经过科学验证的四维模拟。真正的四维旋转和切片可以作为后续内容模块。

电影是空间结构与材质的视觉参考。开发 agent 应检查可用的官方制作资料和参考图，记录结构、光线、构图与运动特征；下文的颜色和尺寸是为 Mathverse 提出的实现值，不是电影实测值。

视觉自检：关闭数学内容和所有后期效果后，空间仍应具有结构性、纵深和电影式尺度感。若只剩一条普通隧道，应回到结构设计阶段。

## 3. 第一次访问：门与连续进入

### 3.1 门外构图

首屏是全浏览器内容区的白色世界，留出大面积空白。门立于画面中央，可略偏下，具备真实厚度和很淡的接触阴影。背景与地面平滑融合，没有清晰地平线。

门的实施默认值：

| 项目 | 起始值／要求 |
|---|---|
| 世界单位 | 约定 1 unit 约等于 1 米，只作为设计尺度 |
| 门尺寸 | 宽 1.25、高 2.4、厚 0.08 unit |
| 门位置 | 门洞位于 z = 0，底部 y = 0 |
| 初始摄像头 | 大约 (0, 1.55, 3.8)，瞄准门的中心附近 |
| 开启方向 | 向门内开启；铰链位于门边；最大开启角约 100° |
| 阴影 | 淡、柔，只用于交代门与地面关系 |
| 品牌文字 | 小号 Mathverse，与门保持足够间距 |
| 提示 | 简短的“推门进入”，兼容按钮与门体点击 |

门板和门框采用三维几何。按钮用真实 HTML button 实现，支持鼠标和键盘。门体 hover 只轻微改变门缝亮度或把手反馈；不开启夸张形变。

点击门的瞬间触发开门，不要求用户学习拖拽门板。门前拖拽不控制空间视角，避免首屏意外偏离构图。

### 3.2 入场节奏

以点击时刻为 t = 0，以下时间可以在预览后调节：

| 时间 | 发生的事情 |
|---|---|
| 0–0.2 秒 | 按钮响应、提示淡出、启动门板运动 |
| 0.2–1.6 秒 | 门逐渐打开，门缝显露深色世界和缓慢变化的结构 |
| 0.7–3.6 秒 | 摄像头前进，通过门洞；门框从视野边缘离开 |
| 3.0–4.2 秒 | 接入持续前进路径，开放扭头交互，出现一次简短操作提示 |

这些动作应重叠形成连续运动，不能硬切白场和深色场景。入场末端的位置、方向、速度都要平滑接上探索路径。摄像头在门板足够打开后才穿过门洞，不能穿过门板、门框或墙面。

门内结构在门打开时就应可见，并已缓慢动态。白色空间与深色空间之间通过实际遮挡、光线和渐进环境变化过渡。优先在一个三维场景内完成门内外的空间连续性，避免两个无关视频式画面拼接。

白色地面不能无限延伸到门内遮住数学世界。可使用局部门前舞台与白色背景；门洞附近布置具有厚度的边界，让门缝看得到后方场景。

必须处理“门外看不到周围的深色世界”：仅放一扇门不能遮住门后整片结构。首版使用与白色背景同色的、覆盖门外视野的边界平面，并为门洞留出真实开口；门板关闭时遮住开口，打开后通过开口看到门内。边界无明显边缘，视觉上仍是白色空间中央的一扇门。门内首批结构都位于该边界后方；生成系统不能在开门前把后方缓存生成到门外。不要仅靠全屏淡黑遮罩伪装空间穿越。若采用门户模板／裁剪方式替代，必须保证门板遮挡、穿越和回望都成立。

场景加载期间保留白色首屏和状态文字。门内最低必需资源准备好后才开放进入；失败时给出可操作的重试或普通内容入口。不要用无限旋转的加载动画遮住门。

默认每次新会话展示门。重复访问可以提供低强调的“直接进入”；是否记忆访问状态作为后续产品选项，第一版不自动改变入场逻辑。

## 4. 门内空间：结构与生成规则

### 4.1 构成语法

空间由矩形／立方结构、细密的层叠框架、具有书架节奏的横纵分隔和局部光窗组成。结构在多个方向延伸，局部的重复与变化共同形成整体。

至少存在三个尺度：

| 尺度 | 形态 | 用途 |
|---|---|---|
| 大尺度 | 延伸的框架群、结构轴、成组光窗 | 建立庞大世界的方向和轮廓 |
| 中尺度 | 反复排列的隔层、框架与嵌套单元 | 建立层次、节奏、视差 |
| 小尺度 | 局部纹理、数学节点、少量线条 | 提供可发现的细节 |

框架必须有实体厚度和明暗面；远处可逐渐简化为轮廓。初始 cellSize 取 6 unit，框架粗细从 0.04–0.12 unit 调节；近处主要构件可更厚。细线在目标分辨率下不应形成严重闪烁或摩尔纹。

主路径附近留出通行带。结构允许靠近画面边缘掠过，不能穿进摄像头。初始建议路径中心周围至少保留约 1.6 unit 的安全半径，并结合摄像头近裁剪面、视野和构件包围盒检查。

### 4.2 空间布局

第一版以一条平稳的深入路线串联若干区域。两侧、上方和后方有可观察结构；部分开口能看到另一组不同方向的重复结构。避免所有结构都沿前进轴对称排列，否则会变成单调的走廊。

空间需要有节奏：结构密集段 → 局部开阔段 → 可发现数学对象的区域 → 再进入更深的结构。密度变化保持连续，不做强烈场景切换。

第一版路线先用直线或极低曲率曲线。弯折只在基础手感通过后加入，保持稳定的世界上方向。整体结构不围绕摄像头旋转。

### 4.3 有限资源中的持续深入

使用分段生成与复用，不不断累积 Mesh。以 pathDistance 为依据，保留前方、侧方和后方的一定范围。每段拥有固定 seed、稳定 chunkId 和固定节点 ID，同一段重新进入时内容不能随机改变。

初始可使用：前方 8 段、后方 5 段；每段约 6 unit。实际段数以回望视野、雾化距离、性能和空间安全共同调节，不把这些数字写死在业务代码中。

用户可以回头，因此不能只在摄像头前方生成内容。几何只在视野外、或已被远处衰减完全隐藏时回收。若某段仍在可见范围内，延迟回收；用有限的缓存上限和雾化范围保证资源有界。选中的数学节点在阅读期间保持有效。

当坐标长期增长时使用浮动原点：保留逻辑路径距离，在渲染空间中同步平移摄像头、场景、节点、拾取数据与观察状态。先保证短时原型，再在持续运行阶段加入；不允许只移动摄像头导致结构跳变。

### 4.4 空间自身的动态

动态分为三类，并与摄像头运动区别开来：

- 结构呼吸：少数组件缓慢伸展、改变间距，典型完整周期 25–60 秒，幅度约为 cellSize 的 0.5%–1.5%。
- 光的变化：局部光带沿结构缓慢移动，或一组光窗逐渐显露，不做高频闪烁。
- 数学对象变化：曲线生成、曲面缓慢变形、切片或投影变化；第一版只做一个代表性样例。

主体空间保持稳定，大约只有局部构件参与显著变化。禁止所有物体统一漂浮、同相位呼吸或高速旋转。结构动画的最大范围必须包含在安全检查与包围盒中。

第一版用廉价的材质参数与局部变换表达变化。复杂体积光、屏幕空间效果和大规模顶点形变属于后续增强。

## 5. 摄像头、路径与弹性扭头

### 5.1 职责分离

TravelRig 负责摄像头沿路径的位置；LookController 负责相对于路径基准方向的观察角；FocusController 负责选中对象时的观察层与暂时接管；MotionDirector 负责状态之间的速度和时间衔接。

运行概念：

```text
路径位置 = P(pathDistance)
pathDistance += 当前前进速度 × dt
探索方向 = 路径基准方向 × 用户观察方向
阅读方向 = 聚焦过程中平滑过渡得到的稳定观察方向
```

路径用弧长或近似弧长距离采样，不能把曲线的均匀参数当成恒定速度。第一版直线路径可简化。路径上方向始终稳定，禁止不受控的滚转。

只有一个模块最终写入摄像头 transform。禁止拖拽控制器、聚焦动画和入场动画同时各自写 camera.position／quaternion。

### 5.2 速度规则

摄像头采用透视投影，初始垂直 FOV = 55°，near = 0.05、far = 100 unit。窗口宽高比由容器更新，首版不做移动过程中的 FOV 呼吸或变焦。远处衰减距离必须小于有效生成范围和 far，回望时也不能露出场景边界。

以 vExplore = 0.35 unit/秒作为起点；cellSize = 6 时，大约 17 秒经过一组主要结构。视觉手感优先于这个数值，速度要能让用户辨认与选中对象。

| 状态 | 目标速度 | 备注 |
|---|---|---|
| 门前 | 0 | 固定初始构图 |
| 入场 | 独立时间曲线 | 比探索前进更快，但平滑接入 |
| 探索 | 1.0 × vExplore | 持续、稳定 |
| 悬停候选对象 | 0.75 × vExplore | 停留约 250ms 后轻微减速 |
| 聚焦／阅读 | 0.06 × vExplore | 保持非常慢的非零位移 |
| 退出阅读 | 从 0.06 渐变到 1.0 × vExplore | 约 1.5–2 秒平滑恢复 |

退出后略快于阅读，默认恢复原探索速度，避免突然冲刺。若预览中需要额外“继续旅程”的感觉，可把恢复末段调到 1.05–1.10，之后回到 1.0，但不作为首版必要效果。

速度变化使用基于 dt 的阻尼或平滑时间曲线，不能瞬间切换。hover 不重复触发新的减速动画。连续悬停不同对象时使用当前速度作为过渡起点。

### 5.3 拖拽与方向

- 只在三维探索区域内按住鼠标左键拖动才转头。
- 拖动向右，观察向右；向上，观察向上。统一方向，在首个原型中验证。
- 水平可以完整回望，使用连续角度累计；跨越 ±180° 时不能反向大幅旋转。
- 垂直范围初始为 ±55°，最后约 7° 进入柔软边界。
- roll 恒为零；不模拟走路点头、呼吸摇晃或随机手持镜头。
- 松手后停在用户选择的方向，不自动归正。
- 不开启 Pointer Lock；无需隐藏系统鼠标。
- 滚轮不控制自由缩放、前进速度或路线；阅读面板可正常滚动。

鼠标灵敏度建议以视口宽度归一化：横向拖动半个视口，观察约转动 90°。设置速度上限，避免极快拖拽或异常 pointer delta 造成视角突变。

### 5.4 弹性算法要求

维护 targetYaw／targetPitch、actualYaw／actualPitch 和角速度。使用基于时间的阻尼弹簧追踪目标，或能实现同样手感的稳定算法。禁止固定每帧 lerp 0.1，禁止以帧数定义速度。

可调起点：自然频率约 3Hz，阻尼比约 0.9–1.0。每帧实际积分步长不超过约 1/120 秒；用子步或解析解维持稳定。隐藏页面恢复时重置时间基准，单次 dt 上限建议 0.05 秒。

验收目标：输入后下一帧开始响应；普通拖拽收尾约 0.2–0.4 秒；只有极小的过冲，且一次收住。减弱回弹优先于表现弹簧效果。30／60／120Hz 下运动速度和收尾时间基本一致。

### 5.5 聚焦与恢复的方向衔接

点击时保存用户观察角度。聚焦只缓慢改变观察方向，将选中对象引向适合观看的位置，禁止额外的突然飞行或大幅横向位移。

阅读期间主场景的拖拽扭头停用；用户可以正常选择文字、滚动说明。退出时先从当前方向平滑过渡到保存的用户观察角度，再恢复自由拖拽。若路径基准有变化，按当前路径基准恢复用户相对角度，不回到旧摄像头位置。

“看向前方”是可选的轻量按钮，操作后缓慢归正。第一版路线固定时，只需要一个低强调的方向提示，不加入复杂地图。

## 6. 数学内容、发现与阅读

### 6.1 第一版内容范围

先放 6 个独立节点，覆盖不同呈现方式：

- 2 个公式节点：例如欧拉恒等式与高斯积分。
- 2 个图形节点：例如单位圆与莫比乌斯带。
- 1 个人物节点：先以姓名、时代和人物位置占位；有可靠素材后再加入肖像。
- 1 个关系节点：演示公式、图像与概念之间的连接。

以上仅用于验证框架，不要求第一版建设完整数学数据库。可先选择欧拉恒等式、单位圆、复数旋转组成一个关联示例。人物资料、年份、肖像与数学解释在内容阶段核对；不生成未经核实的人像或生平作为真实资料。

核心内容可以排布在不同高度与方向；第一个易发现节点在入场后立即可见，另一个位于侧面，促使第一次拖拽。后续节点沿路径按节奏分布，不能依赖刷新随机位置。

### 6.2 节点显示层级

远处只显示轮廓和轻微光；进入可发现范围显示标题或主要形态；hover 显示短提示；点击进入观察层与说明。显示阈值有缓冲区，不能随距离或角度反复闪烁。

节点本体保留世界位置。公式可使用 KaTeX 排版结果生成透明纹理，图形使用真实几何。只有短标签可以适度面向摄像头；整片内容不能全部作为始终朝向用户的二维卡片。

每个视野中的高强调节点建议不超过 3 个。其余内容保留低强调轮廓。数学主题可改变对象形态、布局与运动，颜色始终遵循统一的少色系统。

### 6.3 拾取与点击判定

用射线拾取节点；将附近实体遮挡结构纳入遮挡判断，比较节点与阻挡面的距离。候选目标必须可见且可发现，不能隔着实体框架被选中。

可扩大合理的拾取几何，使小对象易点击，但扩大的 hit area 同样要受遮挡规则约束。实例化结构可作为 occluder，并通过 instanceId 等数据映射到相应构件。

记录 pointerdown 起点与整个手势的最大移动距离。超过 6 CSS px 视为拖拽，pointerup 不能再点击节点。使用 Pointer Capture；pointercancel、失焦、拖出画布和释放都应正确结束手势。HTML 控件与阅读面板消费事件，不能让点击穿透到场景。

### 6.4 观察层：解决持续移动与阅读稳定的冲突

阅读时背景仍向前缓慢移动，但选中对象和说明不能因前进滑出屏幕。

实施方案：保留原节点的逻辑世界位置；创建其观察副本，呈现在独立的观察层。观察层具有稳定构图，背景继续运行。进入时做匹配形态与位置的过渡，再淡出世界中的本体表现，避免一瞬间出现两个相同对象。

第一版可以将原节点淡出、观察副本淡入，过渡约 0.5–0.8 秒；精确的屏幕空间形态匹配属于增强项。观察副本共享几何与材质资源，不重复创建昂贵资产；退出观察层时不能释放仍由世界节点使用的共享资源。

可使用同一 renderer 的独立观察 scene：先绘制世界，再清理深度缓冲绘制观察层，保留观察对象内部的正常深度关系。不能简单让所有观察几何 depthTest = false，否则曲面的前后遮挡会出错。React Three Fiber 中需明确最终渲染职责与后期合成顺序，不能出现重复渲染循环。

说明使用稳定的 HTML 阅读面板。阶段 C 的“左侧对象、右侧窄阅读区”保留为历史基础表现；当前窗口样例采用第 16 节的构图：窗口整体约占画面 80%，外部空间约占 20%且持续可见。内部世界、公式、正文与控件编排在窗口内，正文需要时内部滚动。桌面窗口尺寸改变时保证文字和操作完整。

面板至少包括标题、主要公式或图形说明、简短解释、关闭动作。关闭按钮和 Esc 都可退出。打开时管理键盘焦点，关闭后返回进入阅读的控件或相应内容入口。Canvas 外保留可键盘访问的简洁内容入口，不要求用户只能通过精确点击三维对象阅读。

阅读期间不自动收起、不超时关闭、不自动跳到下一个节点。即使阅读持续数分钟，观察层、节点数据与资源仍有效。

退出时，若原节点仍在合理视野中可渐变回世界表现；若已走过，不强行拉回旧位置，直接淡出观察副本并继续旅程。保留节点在内容入口中的可访问性。

### 7.1 建议色板

| Token | 起始颜色 | 用途 |

| doorWhite | #F0F0EB | 门板与门框的微弱区分 |

| warmLight | #E6C28F | 少量光窗与高亮 |

颜色是初始配置，可根据实际渲染调节。深色区域必须保留实体结构的可辨明暗，不能全部压成纯黑；发光区域保留细节，不能全部过曝成白斑。

正文与按钮按实际背景验证对比度。正文建议至少 16 CSS px；低强调提示也要可读。细字体只用于少量大标题，数学公式重视清楚和排版。

### 7.2 材质和光线

主体是暗色哑光材质，局部可以有暖灰／棕灰的实体质感。采用少量有方向的主光、低强度环境补光与自发光光窗，远处通过雾化或材质衰减逐渐消失。

少量 Bloom 仅强化光窗和极亮内容，控制阈值与亮度。结构本身不全部发光。第一版不启用重度景深、镜头模糊、色散、频繁曝光变化和全场动态阴影。

门外可使用简化接触阴影；门内优先用材质层次、构件明暗、静态纹理或局部烘焙感建立体积。没有资产时先用真实几何、简单材质与方向光完成。

### 7.3 界面

探索时仅保留小号品牌、必要的内容入口和“看向前方”。第一次进入后显示“拖拽环顾，点击探索”约 3 秒；开始拖拽后提前淡出。

开发调参面板只在开发模式可见，不进入正式产品界面。默认无声音；音效与声音入口作为后续独立工作，不影响首版验收。

提供用户主动暂停运动的低强调入口，并尊重 prefers-reduced-motion：保留空间构图与内容访问，关闭弹性过冲，默认不自动前进，可由用户主动开启。正常模式下仍严格执行阅读时非零位移。页面隐藏或失焦属于系统暂停，不改变用户对正常阅读的要求。

若从零建立独立原型，默认采用 TypeScript + Vite + React + Three.js + React Three Fiber。现有项目若为 Next.js，则把三维运行部分置于客户端边界，复用原项目构建工具。非 React 项目可直接采用 Three.js，不为本动效额外迁移整个网站。

选择稳定兼容的 React／React Three Fiber 版本，记录确切版本并提交 lockfile；安装前以官方文档核实兼容性。第一版使用 WebGL2 渲染路径，不以 WebGPU 或 alpha 版本作为必要依赖。

### 8.3 状态机

主状态：WHITE_IDLE → OPENING → ENTERING → EXPLORING → FOCUSING → READING → RETURNING → EXPLORING。

hoverCandidate 和 dragging 是探索状态内的交互状态；文档隐藏、失焦或用户暂停是独立的 suspended 标志。资源错误具有单独错误状态与重试路径。

| 状态 | 摄像头职责 | 交互许可 |
|---|---|---|
| WHITE_IDLE | 固定构图 | 点击／键盘开门 |
| OPENING | 入场编排 | 防重复触发；可选择直接进入 |
| ENTERING | 入场路径 | 暂不开放自由扭头 |
| EXPLORING | 路径 + 用户方向 | 拖拽、悬停、选择内容 |
| FOCUSING | 减速 + 方向过渡 | 可退出；禁止重复聚焦 |
| READING | 极慢路径 + 稳定观察层 | 阅读、滚动、关闭 |
| RETURNING | 恢复观察角度 + 恢复速度 | 禁止重复进入动画，完成后开放探索 |

快速关闭聚焦时，以当前动画值开始返回。重复点击同一个节点不重启聚焦。所有过渡可取消并释放相关监听，不遗留竞争动画。

## 9. 性能与桌面范围

只做电脑浏览器，但需要处理不同桌面窗口尺寸、设备像素比、页面缩放和电脑 GPU 能力。验收视口包括 1280×720、1440×900、1920×1080、2560×1440，并补充浏览器窗口缩放和 200% 页面缩放时的文字可访问性。

以确定的测试设备、浏览器和画质档位记录性能。目标是 1080p 常规桌面设备探索时接近 60fps，目标 p95 帧时间不超过约 20ms；这属于项目目标，不是对未知电脑的性能承诺。测试必须记录硬件、DPR、效果开关及样本时长。

初始工程预算：主要世界绘制调用控制在约 100 次以内，整体含观察层和后期约 150 次以内；初始活跃三角形预算约 30 万；DPR 从 1–1.5 开始，上限 2。预算是调优起点，可以根据实测修改并解释。

实现要求：

- 重复实体框架使用实例化或合并几何；共用材质、几何与纹理。
- 远处减少细节，剔除不可见结构；内容纹理按需要加载。
- 主要材质预编译与纹理预上传，检查首次开门和首次聚焦的卡顿。
- 连续运动时使用持续渲染；不能在背景仍动画时宣称按需渲染可直接省电。页面隐藏、系统暂停或全部运动停止时再停帧／按需渲染。
- 自适应画质先降低 DPR、Bloom 分辨率和远处细节，不改变内容可访问性与交互规则。
- 监测帧时间时使用稳定窗口和上下阈值，避免画质来回跳。
- 持续运行期间 Mesh、geometry、texture 与 listener 数量不能无界增长。
- 浏览器失焦或隐藏后暂停路径与动画时钟；恢复时不补跑离开的时间，不发生摄像头跳跃。
- WebGL2 创建失败或 context 丢失时，保留 HTML 内容入口，提供恢复动作，不能只出现黑屏。

## 10. 开发阶段、交付件与验收门槛

实施顺序有依赖。后续阶段建立在前一阶段的可运行成果上；发现问题时先修复基础，不用增加粒子或后期效果掩盖。

### 阶段 A：工程接入与白盒空间

任务：检查项目、明确依赖、建立页面与三维画布、白色门前、门板铰链、基础空间结构、直线路径、基础自由转头。暂不放正式内容和 Bloom。

交付：可运行预览；门前／门后截图；项目启动方法；依赖和集成位置说明；基础空间参数配置。

验收：门前构图正确；进入空间后能识别近、中、远三层；转头能看到侧面和后方；前进与转头独立；几何不穿越摄像头；结构具有多方向纵深。

### 阶段 B：入场与完整镜头手感

任务：完成连续开门穿越、入场速度接续、弹性扭头、上下柔软边界、速度状态、失焦暂停与恢复。

交付：完整可交互预览；约 20–30 秒录屏，覆盖门前、进入、扭头和回望；调参配置；不同帧率下的运动检查结果。

验收：没有白黑硬切；没有穿门；拖动立即响应并柔和收尾；不自动归正；没有滚转；快速拖动后稳定；失焦回来不跳。

### 阶段 C：数学节点与完整阅读循环

任务：接入 6 个节点、发现层级、hover、遮挡拾取、点击与拖拽区分、观察层、阅读面板、关闭与方向／速度恢复。

交付：至少一种公式和一种三维图形可完整阅读；一条数学关联示例；内容与布局配置；交互检查结果。

验收：拖拽结束不误点击；遮挡对象不能被隔空选中；阅读速度约探索速度的 6%，不是零；阅读内容稳定；读数分钟后不会失效；退出保持当前位置并平滑加速；共享资源正常。

### 阶段 D：电影式视觉与空间动态

任务：先按第 16 节制作欧拉主题的数学窗口样例，建立共享参数的关联世界、人物痕迹与 80%／20%阅读构图；再调整结构密度、实体厚度、材质明暗、光窗、远处衰减、局部结构变化与数学世界动态；最后加入有限 Bloom。

交付：四个代表画面——白色门前、门缝窥见、结构内部、阅读状态；完整窗口样例与关联变化演示；最终运动录屏；正式视觉配置。

验收：窗口具有边框厚度、遮挡与内部视差；欧拉组各窗口的变化由同一数学参数驱动；阅读时窗口约占 80%，外围约 20%保留可辨认的真实空间运动；对象与正文稳定；关闭 Bloom 后仍有体积与纵深；少色系统一致；暖光克制；没有强烈频闪或大面积过曝。

### 阶段 E：持续运行与桌面交付

任务：分段缓存与复用、长期坐标处理、质量档位、资源预热、浏览器窗口尺寸检查、上下文异常处理、生产构建检查。

交付：完整运行说明、硬件明确的性能报告、桌面截图、验收清单、内容扩充方式、已知限制。若需要部署，按用户实际指定的环境另行执行，本方案不预设部署服务。

验收：连续探索至少 10 分钟；至少一次持续阅读 3 分钟；重复进入／退出阅读 20 次；实例与纹理数量趋于稳定；没有明显段落跳出、断裂、黑屏或异常日志。检查长时间阅读退出时原节点已远离的分支。

## 11. 验证与报告要求

自动验证集中在容易回归的运动与状态逻辑：

- 同一段模拟时长，在 30／60／120Hz 下路径总距离基本一致，偏差目标小于 1%。
- 不同帧率下弹性控制器有限、稳定、角度边界正确，收尾时间相近。
- 6px 手势阈值及取消事件正确区分拖拽与点击。
- 状态转换、聚焦中关闭、重复点击、隐藏与恢复不出现两个摄像头写入者。
- 阅读目标速度非零；恢复速度连续。

视觉与真实 GPU 性能必须在可交互浏览器中检查。静态截图不能证明镜头手感或帧率；无 GPU 的自动环境不能代替目标电脑性能报告。没有测量到的项目标为未测，不能写成已通过。

视觉检查至少覆盖：门板运动与门洞遮挡；首次揭示空间；第一次拖拽；侧视与回望；悬停；聚焦；长时间阅读；退出；窗口缩放；隐藏后恢复；禁用 WebGL 的内容入口。

每阶段完成后 agent 应报告：已实现行为；启动／预览入口；关键截图或录屏；实际验证结果；未完成项与真实阻碍；下一阶段任务。不能只报告文件改动列表。

## 16. 已确认的数学窗口方案与阅读构图

### 16.1 窗口与内部世界

每扇窗口拥有正在发生的内部世界。公式提供世界的运行规律，图形让规律可见，人物以发现规律的作品痕迹建立联系。窄开口内部可以呈现远大于外框的尺度；靠近和转头时，内部景象产生视差，外框保留厚度、阴影与遮挡。公式可以布置在窗框内侧或随接近逐渐显露。

### 16.2 第一组：旋转与欧拉

先做单位圆、复指数、欧拉恒等式和欧拉人物四个关联窗口。前三者由同一角度参数驱动：单位圆显示光点与半径，复指数世界将旋转展开为螺旋与周期，欧拉恒等式在半周位置显露对应关系。调整一扇窗口的参数，其余窗口同步响应。

螺旋是复数旋转随参数展开的视觉表达；其截面、相位与单位圆一致，公式与几何数值保持正确。安排一次安静的对齐发现：合适视角下，各窗口中的轨迹在画面上形成整体关系，继续转头后重新分离。

### 16.3 四维感与连接规则

多扇窗口可以同时呈现同一数学对象的不同状态。开口、背面和重复框架组成可以逐渐辨认的连接；局部结构缓慢对齐并再次分离，形成更大整体的短暂显露。镜头保持稳定上方向，路径与用户扭头仍然分离。

同一对象的多个状态并置是视觉叙事规则。实际四维几何区域采用明确的四维旋转、三维切片或投影算法。两种表达在内容和技术说明中各自明确；首轮先把欧拉主题的空间关系做完整。

### 16.4 数学家与思想痕迹

人物窗口采用更安静、接近人的尺度。欧拉窗口以核实过的作品片段、纸页、符号与名字构成；一个关系可以从纸页延伸到相邻的数学世界。肖像在深入阅读后出现，素材与出处需核实。抽象的思想现场作为艺术设计，不冒充真实历史房间或未经证实的手稿。

## 17. 光影与粒子实施补充

本轮实施的光线气质为冷灰石墨中的暖色余光。主体框架降低自发光，保留受光面、暗面和掠射轮廓；暖光集中在窄窗边缘、数学标记和连接通道。门外继续保持明亮白场，过门时按镜头位置平滑衔接环境补光与色调处理。空间运动、粒子与灯光变化使用原有时钟，定格、失焦和恢复规则保持一致。

程序化光幕具有世界位置、深度测试和远处衰减。它是艺术性的空气感近似，不称为物理体积光。微尘固定种子、分段复用；光幕按固定世界段落延续，保留重合段的位置与相位。连接光点使用弧长路径和端点缓慢转向。数学窗口中的粒子沿圆、螺旋、高斯曲面和莫比乌斯边界运动，人物窗口仅保留少量微尘。

新增粒子资产预算为 2496 个点，分别是空间微尘 1440、连接光点 96，以及六个内部世界各 160。该预算是本轮可调实现值，探索时内部世界仍轮换绘制。粒子不参与拾取、不覆盖正文，不用高频闪烁表达活力。

最终渲染由现有观察合成器统一执行：内部窗口纹理 → 主场景与阅读场景的 HDR 合成 → 高亮阈值 Bloom → 曝光与 ACES/sRGB 输出 → FXAA。白色门前不启用 Bloom，HTML 正文与操作保持清晰。关闭 Bloom 后仍需具有可辨的实体厚度与空间层次。

光影配置统一放在 `src/mathverse/config/atmosphere.ts`。浏览器验证与范围以光影报告为准。欧拉人物故事继续按第 18 节实施；精确视角拼接与阶段 E 的完整交付验收仍需继续，不将光影改动等同于全部阶段完成。
